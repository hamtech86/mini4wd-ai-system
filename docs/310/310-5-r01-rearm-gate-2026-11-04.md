The implementation keeps two gates independent:

1. RawLog package recovery must report success.
2. Actuation re-arm must independently establish that every prior nonzero command has a trusted terminal-safe outcome, plus an explicit operator decision and independent device-safe-state confirmation.

The sidecar journal records a command intent, write/flush result, exact ACK identity, and terminal-safe reconciliation. Its `intent_then_send()` wrapper fsyncs the intent before invoking the nonzero-send callback, records a callback exception as UNKNOWN where possible, and never retries. Its identity tuple is `command_id`, `command_type`, `session_id`, full `boot_id64`, and `stage_context_id`. The journal is append-only, SHA-256 hash-chained, and fsyncs each record and its containing directory. Torn/corrupt history fails closed. A short/unknown write, failed/unknown flush, missing or mismatched ACK, missing terminal state, or corrupt journal blocks nonzero-send callback invocation. There is no automatic retry API.

If command outcome is unknown, the only modeled route to a terminal-safe state is an explicit operator reconciliation record with a non-empty decision ID and an independently confirmed device-safe-state assertion. RawLog recovery alone cannot create that record.

The restart tests reconstruct new journal/gate objects over the same test filesystem; they are not real process-kill or power-loss tests. The serial write/partial-delivery states are represented by injected lifecycle outcomes, not a live serial transport.

## Remaining integration and evidence gaps

R01 is **not integrated into `SequenceController` / `ProtocolClient` production paths**. The current production interface still exposes PWM-oriented send/ACK values rather than the complete command/session/boot-epoch/context identity required by this journal. The implementation must not invent wire ACK fields. The current RawLog recovery inhibition marker in `engine.py` is a storage-recovery guard; it is not proof that the independent actuation gate is wired into every ARM/nonzero path.

Before R01 can be considered for acceptance:
- Integrate the gate into every production ARM/nonzero-send entry point without bypass paths.
- Resolve how trusted RawLog recovery state and the independently approved operator reconciliation decision are supplied to the gate.

- Add actual process crash/restart injection at the remaining write/flush, ACK evidence, and terminal evidence boundaries. A host process restart is not a substitute for power-loss durability testing.

## 2026-11-09 司令塔訂正：R01のリスクベース簡素化

従来候補の「全nonzero commandについてintent/write/flush/ACK/terminal-safeを個別に同期fsyncし、hash-chain journalへ保存し、各履歴にoperator decision IDと独立物理safe-state assertionを要求する」設計は、現行のリスク許容度に対して過剰な可能性がある。これをそのままProductionへ統合することは要求しない。

### 維持する最小要件（KEEP）
1. Arduino reset後はfirmware setupでPWM=0、direction GPIO LOWを設定し、device stateはIDLEから開始する。ARMはホストの明示操作が必要であり、reset前のPWM/STARTを自動再実行しない。
2. PC側は以前のnonzero commandを自動再送・自動再開しない。
3. write/flush/ACK/STOPの結果が不明な場合はUNKNOWNと表示・記録し、SUCCESSや物理停止確認に読み替えない。
4. RawLog/Evidenceのrecovery markerは、未完了作業の発見後に自動削除しない。markerがある間は自動ARM/非zero sendを拒否する。
5. UNKNOWNやrecovery markerが残る状態では、システム自身の自動復旧・自動再始動を行わない。

### 緩和・削除する要件（RELAX / REMOVE）
- 全nonzero commandごとの同期fsyncおよび個別hash-chain lifecycle journalは、一律必須としない。
- 過去の全commandに対する個別operator terminal-safe recordを要求しない。
- 過去の全commandについて、独立センサー等による物理safe-state証拠を個別に取得する要求を削除する。
- RawLogの完全復旧とactuation journalの完全復旧を二重に要求する複雑な統合を、現時点の310-5完了条件にしない。
- 既存ActuationSafetyJournal候補は設計検討・テスト資料として残してよいが、Production経路へ統合する前提にしない。

### 運用者による一回の復旧確認（新しい最小案）
中断・reset・通信断・不明な指令結果が発生した場合:
1. 画面でUNKNOWN / RECOVERY REQUIREDを表示し、過去コマンドを再送しない。
2. 運用者が手の届く主電源スイッチでモーター電源をOFFにする。スイッチが実際にdriver/motor電源を遮断する配線であることは、HW01の無通電配線確認で同定する。
3. 回転が停止したことを目視し、再始動しない状態を確認する。電源状態を判断できない場合はmarkerを解除しない。
4. 運用者が一度だけ明示的に「主電源OFF・復旧確認済み」を記録してからrecovery markerを解除する。解除は自動処理や起動時処理にしない。
5. 新しい測定は新しいsession/boot identityで開始する。旧コマンド・旧ACKを再生しない。

この手順は、運用者による主電源遮断を用いるリスク受容方針であり、独立ハードウェアcutoffの物理証明と同等ではない。スイッチがdriver/motor電源を遮断しない場合、または停止操作が現実に困難な設置の場合は、独立cutoffの必要性を再評価する。

### 現在の実装状態
- Firmware source inspection: setup() calls safe_outputs() before protocol processing; PWM output is set to 0 and D7/D8 are set LOW. A valid boot identity initializes device state to DEVICE_IDLE. This is source evidence only; physical reset waveform/output behavior is NOT RUN.
- Host production paths: persistent recovery-marker checks exist at Protocol V1, Protocol V2 and SequenceController stage-send boundaries.
- Recovery marker release after the operator procedure above: NOT IMPLEMENTED.
- ActuationSafetyJournal production lifecycle integration: NOT IMPLEMENTED and no longer a mandatory design direction under this revised scope.
- Actual power-switch isolation, motor stop after power removal, and reset behavior: NOT RUN; no hardware operation is authorized.

Do not keep the former 38th-item FAIL solely because the full per-command journal/independent physical proof design is not implemented. Do not mark R01 PASS until the release path and host no-auto-resume behavior are implemented and tested. Physical power-switch behavior remains a separately reviewed hardware condition; it is not proven by this host document.

### 2026-11-09 operator-release implementation candidate

PR #193 now adds `measurement_310/recovery_release.py` and `tests/test_measurement_310_recovery_release.py`.

The release command is deliberately manual and is not called by startup or recovery code:

```bash
python -m measurement_310.recovery_release \
  --root /path/to/rawlog-root \
  --operator-id OPERATOR_ID \
  --decision-note "Main switch OFF; rotor visually stopped."
```

The command prompts for the exact phrase `MOTOR POWER OFF`. It refuses release if RawLog incomplete work remains, a marker is symlinked/non-regular, or the operator does not confirm. It durably appends one operator-action record before unlinking existing markers and fsyncs the RawLog root directory afterward. It never opens a serial port, sends STOP/ARM/PWM, or starts a new sequence.

The audit record explicitly labels the physical state as `OPERATOR_ATTESTATION_ONLY_NOT_INDEPENDENTLY_MEASURED`. It does not claim independent electrical confirmation. If the operator cannot establish that the main switch removes motor/driver power and that the rotor has stopped, the marker must remain.

Current code/test status at the time of this amendment: candidate code and tests committed to PR #193; CI result pending. This is not yet R01 PASS or 310-5 acceptance.
