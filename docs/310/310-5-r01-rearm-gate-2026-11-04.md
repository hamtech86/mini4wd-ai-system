The implementation keeps two gates independent:

1. RawLog package recovery must report success.
2. Actuation re-arm must independently establish that every prior nonzero command has a trusted terminal-safe outcome, plus an explicit operator decision and independent device-safe-state confirmation.

The sidecar journal records a command intent, write/flush result, exact ACK identity, and terminal-safe reconciliation. Its `intent_then_send()` wrapper fsyncs the intent before invoking the nonzero-send callback, records a callback exception as UNKNOWN where possible, and never retries. Its identity tuple is `command_id`, `command_type`, `session_id`, full `boot_id64`, and `stage_context_id`. The journal is append-only, SHA-256 hash-chained, and fsyncs each record and its containing directory. Torn/corrupt history fails closed. A short/unknown write, failed/unknown flush, missing or mismatched ACK, missing terminal state, or corrupt journal blocks nonzero-send callback invocation. There is no automatic retry API.

If command outcome is unknown, the only modeled route to a terminal-safe state is an explicit operator reconciliation record with a non-empty decision ID and an independently confirmed device-safe-state assertion. RawLog recovery alone cannot create that record.

## Regression source coverage

The test module contains 18 test functions / 25 parameter-expanded cases covering:
- RawLog recovery alone does not authorize re-arm.
- Restart snapshots after intent, an attempted write without a result, unknown write/flush, successful write before ACK, and ACK before terminal state.
- Failed/unknown write/flush and non-matching ACK identities.
- Exact ACK still requires terminal-safe state and operator confirmation.
- Explicit reconciliation of an unknown outcome.
- RawLog recovery failure blocks otherwise clean actuation history.
- Torn journal, symlink/unreadable journal, command-ID reuse, and out-of-order transitions.
- Boolean `boot_id64` rejection.
- Partial append and fsync failures at pre-terminal evidence boundaries.
- Durable intent fsync before send callback, send suppression when intent fsync fails, and uncertain callback failure recorded as UNKNOWN.

These are source-level host tests. The isolated harness ran the candidate R01 logic and regression cases, but did not constitute a complete repository checkout. The restart tests reconstruct new journal/gate objects over the same test filesystem; they are not real process-kill or power-loss tests. The serial write/partial-delivery states are represented by injected lifecycle outcomes, not a live serial transport.

## Remaining integration and evidence gaps

R01 is **not integrated into `SequenceController` / `ProtocolClient` production paths**. The current production interface still exposes PWM-oriented send/ACK values rather than the complete command/session/boot-epoch/context identity required by this journal. The implementation must not invent wire ACK fields. The current RawLog recovery inhibition marker in `engine.py` is a storage-recovery guard; it is not proof that the independent actuation gate is wired into every ARM/nonzero path.

Before R01 can be considered for acceptance:
- Integrate the gate into every production ARM/nonzero-send entry point without bypass paths.
- Resolve how trusted RawLog recovery state and the independently approved operator reconciliation decision are supplied to the gate.
- Resolve the firmware/wire identity limitation through the appropriate separate design/implementation authority; do not fabricate ACK identity.
- Run the full candidate test module and applicable regression suites on a complete checkout, recording exact command, exit code, test count, output, and evidence hash.
- Add actual process crash/restart injection at the remaining write/flush, ACK evidence, and terminal evidence boundaries. A host process restart is not a substitute for power-loss durability testing.
- Keep physical PWM=0, driver cutoff, and rotor stop outside the claims of this host module.
