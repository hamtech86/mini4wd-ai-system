# 2026-11-11 司令塔方針転換 — 310完了・実用化優先

## 決定

2026-11-11 12:27 UTC時点の司令塔指示を、310プロセスの現行進行方針として記録する。

- 310では、実機安全性の未確認項目が残っていることだけを理由に、310全体または後続のソフトウェア/UI工程を停止しない。
- 310の最低限の完了と実用化を優先する。
- 実機安全性の未確認は、物理安全が確認済みという意味に読み替えない。証拠の状態はPASS / FAIL / BLOCKED / NOT RUN / NOT APPLICABLEで正確に記録する。
- モーターを動かす際に発生する不具合・制約は、310の設計段階で推測して全て解消しようとせず、ベンチマーク等の実際にモーターを動かす工程で実測し、原因を切り分けて吸収・修正する。
- 310のソフトウェア/UI完成と、物理モーター運転・ベンチマークの実施許可は別の判断として扱う。後者の許可を本方針から自動推定しない。

## 工程への適用

### 310-5
- 既に完了しているソフトウェア・ホスト側実装と検証を基に、受入審査を進める。
- 未実施の物理試験（NOT RUN）を、ソフトウェア/ホスト範囲の受入を妨げる一律の完了条件にしない。
- 物理STOP、GPIO/reset波形、電流遮断、電流制限・熱保護などは、実施していないものをPASSとしない。必要な残留制約は、実際のモーター運転工程の作業条件として管理する。
- `HARDWARE_CURRENT_LIMIT_CONFIRMED=false` は、根拠が得られるまで維持する。これを310全体のソフトウェア/UI作業停止フラグとして使用しない。

### 310-6
- UI統合を開始・継続する。既存Qtイベントループへの非ブロッキングtick、開始/STOP、PWM段階・経過時間・状態表示、RawLog v2 ID/個体紐付け、incomplete/faulted保存、履歴・GitHub登録経路を仕上げる。
- 既存のFW identity、ARM/token、STOP、UNKNOWNの扱い、RawLog v2契約、A0/A1独立性、A2/A3参考値限定などの確定契約は維持する。
- ホストテスト・CI・Arduino compile/HEXは、それぞれ実施範囲を明記して検証する。CI/compileを実機動作証明に読み替えない。
- UI統合・ホスト検証の完了を、Arduino接続・書込み・モーター通電・310秒実測の許可と解釈しない。

### 310-7

- 310の完了判定と、ベンチマーク実機試験の結果・実用上の不具合対応を分けて記録する。

- Issue #172のPWM 0〜30検出レシピ等、実機駆動を伴う測定は、仕様・UI・ホスト側の準備と、実際の通電/測定許可を分離する。
- 実機操作は、その操作に対する明示的な実施指示を得てから行う。未承認の接続・書込み・通電・310秒測定は行わない。

## 変更していない事項

- RawLog v1原本の不変保全、RawLog v2独立スキーマ。
- A0=巻線電流、A1=ブラシ安定性の独立観測。A0/A1を平均しない。
- A2/A3は参考値のみで、承認まで制御・停止・異常判定に使用しない。
- 310秒段階進行の主体はPython。
- UNKNOWNをSUCCESSに変換しない。reset/recovery後に過去のnonzero commandを自動再送しない。
- `HARDWARE_CURRENT_LIMIT_CONFIRMED=false` を維持する。
- 物理試験未実施を物理PASSとして記載しない。

この文書は工程方針と作業順序の変更を記録するものであり、個別の物理試験・実機通電の許可書ではない。
